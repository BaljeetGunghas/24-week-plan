Part 1: Anagram Detection

Challenge: Check if Two Strings are Anagrams

Definition: Two strings are anagrams if they contain the same characters with the same frequencies, just in different order.

  • Fundamental string comparison technique
  • Tests understanding of character encoding
  • Common interview question

Visual Example

isAnagram() Function

function isAnagram(s, t) {
  // Anagrams must be same length
  if (s.length !== t.length) return false;

  // Create frequency array (256 chars in ASCII)
  let array = new Array(256).fill(0);

  // Increment count for each char in s
  for (let i = 0; i < s.length; i++) {
    array[s[i].charCodeAt(0)]++;
  }

  // Decrement count for each char in t
  for (let i = 0; i < t.length; i++) {
    array[t[i].charCodeAt(0)]--;
  }

  // Check if all counts are 0
  for (let i = 0; i < array.length; i++) {
    if (array[i] > 0) return false;
  }

  return true;
}

Step-by-Step Execution (Dry Run)

Input: isAnagram("abecde", "aebecd") Step 1: Length check ├─ s.length = 6 ├─ t.length = 6 └─ Continue ✓ Step 2: Create frequency array └─ array = [0, 0, 0, ..., 0] (256 zeros) Step 3: Process string "abecde" (increment) ├─ 'a' (97): array[97]++ = 1 ├─ 'b' (98): array[98]++ = 1 ├─ 'e' (101): array[101]++ = 1 ├─ 'c' (99): array[99]++ = 1 ├─ 'd' (100): array[100]++ = 1 └─ 'e' (101): array[101]++ = 2 Step 4: Process string "aebecd" (decrement) ├─ 'a' (97): array[97]-- = 0 ├─ 'e' (101): array[101]-- = 1 ├─ 'b' (98): array[98]-- = 0 ├─ 'e' (101): array[101]-- = 0 ├─ 'c' (99): array[99]-- = 0 └─ 'd' (100): array[100]-- = 0 Step 5: Verify all counts are 0 ├─ Loop through all 256 indices ├─ All non-zero indices found = 0 └─ Continue ✓ Return: true ✓

Complexity Analysis

Time Complexity

O(n)

Process each string once (3 passes max)

Space Complexity

O(1)

Fixed array of 256 (constant space)

Key Concepts

  • charCodeAt(): Returns ASCII code of character (97='a', 122='z')
  • Frequency Array: Fixed size (256) allows O(1) lookups and updates
  • Two-Pass Strategy: First increment, then decrement to verify balance
  • Space Optimization: O(1) because array size is constant regardless of input

Part 2: Event Loop Deep Dive

What is the Event Loop?

The event loop is JavaScript's mechanism for managing the execution order of code. It prioritizes synchronous code, then microtasks (promises, async/await), then macrotasks (setTimeout, setInterval).

Event Loop Architecture

Classic Event Loop Example

console.log("A");                 // Sync

setTimeout(() => {
  console.log("B");                 // Macrotask
}, 0);

Promise.resolve().then(() => {
  console.log("C");                 // Microtask
});

console.log("D");                   // Sync

Expected Output & Explanation

Output: A → D → C → B Detailed Breakdown: Phase 1: SYNCHRONOUS EXECUTION (Call Stack) ├─ console.log("A") → Executes immediately │ Output: A ├─ setTimeout(...) → NOT executed yet, scheduled to MACROTASK queue ├─ Promise.then(...) → NOT executed yet, scheduled to MICROTASK queue ├─ console.log("D") → Executes immediately │ Output: D └─ Call Stack is now EMPTY Phase 2: MICROTASK QUEUE (All pending microtasks) ├─ Promise.then() → Executes now │ Output: C └─ Microtask queue is now EMPTY Phase 3: MACROTASK QUEUE ├─ setTimeout() → Executes now (0ms delay) │ Output: B └─ Complete! Final Output Order: A → D → C → B

Async/Await Example

async function myFunc() {
  console.log("1");              // Sync
  await Promise.resolve();        // Pause here
  console.log("2");              // Resume in microtask
}

console.log("3");                // Sync
myFunc();                         // Sync start
console.log("4");                // Sync

Output: 3 → 1 → 4 → 2

Execution Trace: Synchronous Phase: ├─ console.log("3") │ Output: 3 ├─ myFunc() called │ ├─ console.log("1") │ │ Output: 1 │ └─ await Promise.resolve() → PAUSE (goes to microtask) └─ console.log("4") Output: 4 Call Stack is now EMPTY Microtask Phase: └─ Resume myFunc() after await ├─ console.log("2") │ Output: 2 └─ Function completes Final Output Order: 3 → 1 → 4 → 2

Quick Comparison Table

Type Queue Priority Examples Blocking
Sync Call Stack 1st Direct code, loops, functions Yes - blocks everything
Microtask Microtask Queue 2nd Promises, async/await, MutationObserver Can starve macrotasks
Macrotask Macrotask Queue 3rd setTimeout, setInterval, setImmediate Happens after all microtasks

Key Takeaways

  • Always synchronous first: Code runs immediately unless explicitly made async
  • Promises execute in microtask: They run BEFORE setTimeout, even if setTimeout is 0ms
  • await = microtask: Async/await is syntactic sugar over promises
  • Microtask starvation: If microtasks keep generating new microtasks, macrotasks never run
  • Event loop repeats: After one macrotask, check ALL microtasks, then next macrotask
