Problem: Smallest Subarray with Sum ≥ Target

Challenge

Goal: Find the length of the smallest contiguous subarray whose sum is greater than or equal to a target value.

Example: Array: [2, 3, 1, 2, 4, 3], Target: 7 → Answer: 2 (subarray [4, 3])

  • Variable-size window required
  • Two-pointer management essential
  • Perfect for stream processing concepts

Approach 1: Brute Force O(n²)

function smallestSubarray(target, arr) {
  let smallestLength = arr.length;

  for (let i = 0; i < arr.length; i++) {
    let sum = arr[i];

    for (let j = i + 1; j < arr.length; j++) {
      sum += arr[j];

      if (sum >= target) {
        smallestLength = Math.min(smallestLength, j - i + 1);
        break;  // Early exit for this i
      }
    }
  }

  return smallestLength;
}

Why This is Inefficient

Issue: For each starting position, we check all possible ending positions. Even with early exit, worst case is O(n²).

Redundant Work: Information from previous windows isn't reused. We recalculate sums we've already computed.

Approach 2: Variable Window O(n)

function smallestSubarray(target, arr) {
  let smallestLength = Infinity;
  let windowSum = 0;
  let left = 0;

  for (let right = 0; right < arr.length; right++) {
    windowSum += arr[right];      // Expand window

    // Shrink window while condition is met
    while (windowSum >= target) {
      let length = right - left + 1;
      smallestLength = Math.min(smallestLength, length);

      windowSum -= arr[left];      // Remove leftmost element
      left++;                       // Move left pointer
    }
  }

  return smallestLength === Infinity ? 0 : smallestLength;
}

Why This Works

  • Single Pass: Right pointer moves 0→n, left pointer moves 0→n (each element visited max twice)
  • Smart Shrinking: When sum ≥ target, shrink from left until we break the condition
  • Optimal Length: Record smallest length before shrinking further
  • State Reuse: Window sum carries from previous iteration

Approach Time Space When to Use
Brute Force O(n²) O(1) Small arrays, simple interviews
Variable Window O(n) O(1) Always preferred!

Node.js Streams & HighWaterMark

Connection to Variable Window

Node.js streams use a similar concept: the highWaterMark is a buffer threshold. When data reaches the limit, the stream pauses. This is like our window shrinking when a condition is met!

Stream HighWaterMark Example

const fs = require('fs');

// Read large file in 64KB chunks
const stream = fs.createReadStream('large-file.txt', {
  highWaterMark: 64 * 1024  // 64KB buffer threshold
});

stream.on('data', (chunk) => {
  console.log(`Chunk received: ${chunk.length} bytes`);
  // Process chunk
});

stream.on('end', () => {
  console.log('File reading complete');
});

Variable Window vs Stream Buffering

Concept Variable Window Stream HighWaterMark
Purpose Find subarray meeting condition Manage data flow efficiently
Expand/Shrink Right pointer expands, left shrinks Buffer fills, then pauses to process
Threshold Sum ≥ target Buffered data ≥ highWaterMark
Action Shrink when threshold met Pause when threshold reached

Why HighWaterMark Matters

  • Memory Efficiency: 64KB buffer for 1GB file doesn't load everything into RAM
  • Backpressure: Prevents buffer overflow by pausing source
  • Real-time Processing: Process chunks as they arrive, not after loading all data
  • Search Analogy: Like finding a keyword in a stream - keep reading until found, then stop

Interview Tips & Optimization Notes

Explain the Inefficiency

Always mention why brute force is O(n²): recalculation of sums for overlapping windows

Key Insight

Two pointers move in same direction, not opposite. Right expands, left shrinks conditionally

Edge Cases

Handle when no valid subarray exists (return -1 or Infinity)

Code Clarity

Use descriptive variable names: windowSum, left, right make logic obvious

Learning Summary

Key Takeaways

  • Variable Window Pattern: Window size changes based on condition, not fixed
  • Two-Pointer Management: Both pointers move forward, creating shrinking window
  • State Preservation: Carry window sum between iterations (don't recalculate)
  • Real-World Application: Stream buffering uses identical concepts
  • Interview Gold: Can explain brute force, optimization, AND practical applications
