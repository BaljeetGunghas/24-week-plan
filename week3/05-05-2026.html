Core Concept: Hash Map Frequency Counting

The Problem

Given array of file extensions: ['jpg', 'png', 'jpg', 'pdf', 'jpg', 'pdf']

Find which extension is most frequently uploaded.

Solution Approach

Key Insight: A Hash Map (or JavaScript Map) gives O(1) lookups. Perfect for counting.

Implementation

function frequencyCounter(arr, k) {
    if (arr.length === 0) return 0;

    // Step 1: Build frequency map - O(n)
    let freqMap = new Map();

    for (let i = 0; i < arr.length; i++) {
        let key = arr[i];
        if (freqMap.has(key)) {
            freqMap.set(key, freqMap.get(key) + 1);
        } else {
            freqMap.set(key, 1);
        }
    }

    // Step 2: Find maximum - O(n)
    let maxFreq = 0;
    let maxKey = "";

    freqMap.forEach((freq, ext) => {
        if (freq > maxFreq) {
            maxFreq = freq;
            maxKey = ext;
        }
    });

    return maxKey;  // Returns: "jpg"
}

const extensions = ["jpg", "png", "jpg", "pdf", "jpg", "pdf"];
console.log(frequencyCounter(extensions, 1));  // Output: "jpg"

Complexity Analysis

Metric Value Explanation
Time Complexity O(n) One pass to build map + one pass to find max
Space Complexity O(n) Worst case: every element is unique
Best Case O(n) Still need to count all elements
Worst Case O(n) All elements unique, full map traversal

Challenge: Top K Most Frequent Elements

The Upgrade

Instead of finding the top 1, find the top K elements.

Example: ['jpg': 10, 'pdf': 8, 'png': 5, 'txt': 2] and K=2

Answer: ['jpg', 'pdf']

Approach Comparison

Approach Time Space Best For
Sort entire map O(n log n) O(n) Simple, small data
Min-Heap (K elements) O(n log k) O(k) Large N, small K
Bucket Sort O(n) O(n) Frequencies are bounded
Interview Insight: "If we have 1,000,000 files but only want Top 3 extensions, O(n log k) saves 20x more time than O(n log n). This is why senior engineers think about K."

Understanding Heaps

What is a Heap?

A heap is a complete binary tree where each parent is smaller (Min-Heap) or larger (Max-Heap) than its children.

  • Min-Heap: Smallest at root. Used for Top K Largest.
  • Max-Heap: Largest at root. Used for Top K Smallest.

Why Min-Heap for Top K?

Logic for "Top 3" items: Step 1: Create Min-Heap, add first 3 items └─ Heap: [5, 8, 10] (min at top: 5) Step 2: Next item has frequency 7 └─ Is 7 > 5 (min)? YES └─ Remove 5, add 7 └─ Heap: [7, 8, 10] Step 3: Next item has frequency 3 └─ Is 3 > 7 (min)? NO └─ Skip it, keep heap same Result: Heap always maintains Top 3 largest! Final answer: [7, 8, 10]

Heap-Based Top K Implementation (Conceptual)

// Conceptual pseudocode (JS doesn't have built-in heap)
function topKFrequent(words, k) {
    // Step 1: Build frequency map
    const freqMap = new Map();
    for (const word of words) {
        freqMap.set(word, (freqMap.get(word) || 0) + 1);
    }

    // Step 2: Create min-heap of size k
    const minHeap = [];

    for (const [word, freq] of freqMap) {
        minHeap.push({ word, freq });

        // Keep heap size = k
        if (minHeap.length > k) {
            // Remove element with minimum frequency
            minHeap.sort((a, b) => a.freq - b.freq);
            minHeap.shift();  // Remove smallest
        }
    }

    // Step 3: Return top k
    return minHeap.map(item => item.word);
}

// Time: O(n log k) vs O(n log n) for sorting!
