Creating HTTP Server

Basic Setup

const http = require("http");

const server = http.createServer((req, res) => {
  // req = incoming request from client
  // res = outgoing response to send to client

  res.setHeader("content-type", "application/json");
  console.log(req.url, req.method);

  // Handle routes...
});

server.listen(3000, () => {
  console.log(`Server running on port 3000`);
});

Request Object Properties

Property Description Example
req.url The path client requested "/profile"
req.method HTTP method used "GET", "POST", "PUT"
req.headers Request headers object { "content-type": "application/json" }

Response Methods

Method Purpose
res.setHeader() Set response headers
res.statusCode Set HTTP status (200, 404, etc)
res.end() Send response and close connection

Route Handling

GET Request Handler

if (req.url === "/profile" && req.method === "GET") {
  res.statusCode = 200;
  res.statusMessage = "ok";

  res.end(JSON.stringify({
    target: "35 LPA",
    status: "In progress"
  }));
}

POST Request Handler - Streaming

else if (req.url === "/profile-update" && req.method === "POST") {
  let body = "";

  // Listen for data chunks
  req.on("data", (chunk) => {
    body += chunk.toString();  // Accumulate
  });

  // All data received
  req.on("end", () => {
    try {
      const data = JSON.parse(body);
      res.statusCode = 200;
      res.end(JSON.stringify({
        data,
        message: `Target updated to ${data.target}`
      }));
    } catch (err) {
      res.statusCode = 400;
      res.end(JSON.stringify({ error: "Invalid JSON" }));
    }
  });
}

Why Streaming?

HTTP request body comes in CHUNKS, not all at once! Why streaming: ✓ Memory efficient (don't load entire file) ✓ Can start processing before all data arrives ✓ Better for large files ✓ Scalability Listening to events: - 'data' event: Each chunk arrives - 'end' event: All chunks received - 'error' event: Network error

HTTP Status Codes

Code Meaning When to Use
200 OK Request successful
201 Created Resource created
400 Bad Request Invalid input
404 Not Found Path doesn't exist
500 Server Error Server crashed

Common Issues & Fixes

Issue 1: Typo in setHeader

// ❌ Wrong - assignment instead of method call
res.setHeaders = ("content-type", "application/json");

// ✅ Correct - proper method invocation
res.setHeader("content-type", "application/json");

Issue 2: No Error Handling for JSON.parse()

// ❌ Crashes on invalid JSON
const data = JSON.parse(body);

// ✅ Graceful error handling
try {
  const data = JSON.parse(body);
} catch (err) {
  res.statusCode = 400;
  res.end(JSON.stringify({ error: "Invalid JSON" }));
}

Native HTTP vs Express

Aspect Native HTTP Express
Body Parsing Manual: req.on('data') Automatic: req.body
Routing Manual if/else chains Clean: app.get(), app.post()
Headers Manual: res.setHeader() res.header() or middleware
Learning Value ✓ High - understand fundamentals Hides complexity

Key Takeaways

  • Native HTTP Module: Foundation upon which Express is built
  • Streaming Data: Listen to 'data' and 'end' events for request body
  • Event-Driven: Node.js is asynchronous and event-based
  • Error Handling: Always wrap JSON.parse() in try-catch
  • Understanding Before Framework: Learn fundamentals with native HTTP, then use Express for cleaner code
