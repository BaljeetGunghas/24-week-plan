Function 1: sumRange()

Purpose

Calculate sum of all integers from n to 1 using recursion to understand base cases and call stack behavior.

function sumRange(num) {
  // Base case: recursion stops here
  if (num === 1) {
    return 1;
  }

  // Recursive case: solve smaller problem
  return num + sumRange(num - 1);
}

Call Stack for sumRange(3)

sumRange(3) → 3 + sumRange(2) → 2 + sumRange(1) → 1 (base case) → 2 + 1 = 3 → 3 + 3 = 6 Stack grows then shrinks (LIFO)

Why Base Case is Critical

// ❌ WITHOUT base case - INFINITE RECURSION
function sumRange(num) {
  return num + sumRange(num - 1);
  // Never stops! Stack Overflow!
}

// ✅ WITH base case
function sumRange(num) {
  if (num === 1) return 1;  // Stop here!
  return num + sumRange(num - 1);
}

Function 2: fibonacciSeq()

Purpose

Calculate nth Fibonacci number where each number is sum of previous two. Demonstrates exponential time complexity problem.

function fibonacciSeq(num) {
  // Base case: first two Fibonacci numbers
  if (num <= 2) {
    return 1;
  }

  // Recursive case
  return fibonacciSeq(num - 1) + fibonacciSeq(num - 2);
}

Time Complexity Problem

Input Function Calls Time Status
fib(5) 15 ~0.1ms ✓ Fast
fib(10) 177 ~10ms ✓ OK
fib(30) 2,178,309 ~30s ⚠️ Slow
fib(40) 331,160,281 Minutes ✗ Very Slow
fib(60) ~1 quadrillion Hours+ ✗ Impossible

Why fib(60) Takes Forever

Naive recursive Fibonacci: O(2^n) complexity fib(60) = ~2^60 = 1 quadrillion function calls Even at 1 million calls/second: 1,000,000,000,000 ÷ 1,000,000 = 1,000,000 seconds = 11+ days of non-stop computation! Lesson: Exponential algorithms are IMPRACTICAL

Solution: Memoization

function fibMemo(num, memo = {}) {
  // Check if already calculated
  if (memo[num]) {
    return memo[num];
  }

  // Base case
  if (num <= 2) {
    return 1;
  }

  // Calculate and store in memo
  memo[num] = fibMemo(num - 1, memo) + fibMemo(num - 2, memo);

  return memo[num];
}

Performance Comparison

Input Naive Calls Memoized Calls Speedup
fib(20) 10,946 39 280x faster!
fib(30) 2.2M 59 37,000x faster!
fib(50) 40 Billion 99 404 million times faster!

Learning Summary

Base Case Essential

Missing base case = infinite recursion

Call Stack Limits

Deep recursion causes overflow

Exponential Problems

O(2^n) becomes impossible quickly

Memoization Magic

Transforms exponential to polynomial!

Key Takeaways

  • Base Case: MUST be present to stop recursion
  • Call Stack: Limited size, typically ~15,000-30,000 calls
  • Exponential Growth: O(2^n) doubles with each increment - watch out!
  • Memoization: Cache results to eliminate redundant calculations
  • Interview Note: Always ask about optimization and mention memoization!
