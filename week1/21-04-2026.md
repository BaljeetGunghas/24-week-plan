# Function Breakdown

## Function 1: moveZeroAtLast() - Write Pointer Approach

### Purpose
Moves all zeros to the end of array while maintaining order of non-zero elements using a write-pointer (count) approach instead of two-pointer swapping.

### Parameters
- `arr` (Array): Input array containing zeros and non-zero values

### Return Value
- Modified array with all zeros moved to end

### Logic Explanation

```javascript
function moveZeroAtLast(arr) {
  // Handle single element
  if (arr.length === 1) {
    return arr;
  }
  
  let count = 0;  // Write pointer - where next non-zero should go
  
  // Single pass through array
  for (let i = 0; i < arr.length; i++) {
    // If current element is not zero
    if (arr[i] !== 0) {
      // Swap current element with position at count
      const temp = arr[count];
      arr[count] = arr[i];
      arr[i] = temp;
      
      // Move write pointer forward
      count++;
    }
  }
  
  return arr;
}
```

**Key Difference from Previous Approach:**
- **Previous (two-pointer)**: Uses pointers from both ends, swaps from outside in
- **Current (write-pointer)**: Single pointer tracks where next non-zero should be written, swaps as it moves forward
- **Result**: Same outcome but different mechanism, and this approach maintains better locality

### Dry Run Example

**Input**: `moveZeroAtLast([0, 1, 0, 3, 12])`

```
count = 0

i = 0: arr[0] = 0 (is zero, skip)
  Array: [0, 1, 0, 3, 12]

i = 1: arr[1] = 1 (not zero)
  Swap arr[0] ↔ arr[1]
  Array: [1, 0, 0, 3, 12]
  count = 1

i = 2: arr[2] = 0 (is zero, skip)
  Array: [1, 0, 0, 3, 12]

i = 3: arr[3] = 3 (not zero)
  Swap arr[1] ↔ arr[3]
  Array: [1, 3, 0, 0, 12]
  count = 2

i = 4: arr[4] = 12 (not zero)
  Swap arr[2] ↔ arr[4]
  Array: [1, 3, 12, 0, 0]
  count = 3

Return: [1, 3, 12, 0, 0]
```

### Edge Cases
1. **No zeros**: `[1, 2, 3]` → `[1, 2, 3]` (no changes)
2. **All zeros**: `[0, 0, 0]` → `[0, 0, 0]` (no changes)
3. **Single element zero**: `[0]` → `[0]` (early return)
4. **Single element non-zero**: `[5]` → `[5]` (early return)

### Time Complexity
**O(n)** - Single pass through array with constant time operations

### Space Complexity
**O(1)** - In-place modification using only count variable

# JavaScript Fundamentals Section

## 1. The Call Stack

### What is the Call Stack?
The call stack is a data structure that keeps track of function calls in JavaScript. It's LIFO (Last-In, First-Out) - the last function called is the first one to finish.

### How It Works

```javascript
function greet() {
  console.log("Hello!");  // Step 3: Executes
}

function start() {
  greet();  // Step 2: Calls greet
}

start();  // Step 1: Initial call
```

**Stack Visualization:**

```
Step 1:        Step 2:          Step 3:         Step 4:
┌─────────┐   ┌─────────┐      ┌─────────┐     ┌─────────┐
│ start() │   │ greet() │      │ (ready) │     │ (empty) │
├─────────┤   ├─────────┤      ├─────────┤     ├─────────┤
│ Global  │   │ start() │      │ start() │     │ Global  │
├─────────┤   ├─────────┤      ├─────────┤     ├─────────┤
│         │   │ Global  │      │ Global  │     │         │
└─────────┘   └─────────┘      └─────────┘     └─────────┘
```

### Important Properties
- **Single-threaded**: JavaScript executes one thing at a time
- **LIFO**: Last function called is first to complete
- **Maximum size**: Exceeding it causes "Stack Overflow" error

## 2. Hoisting

### What is Hoisting?
Hoisting is JavaScript's behavior of moving declarations to the top of their scope before code execution.

### Important: Only Declarations are Hoisted, NOT Initializations

### Variable Hoisting

#### var Hoisting
```javascript
console.log(name);  // undefined (not an error!)
var name = "Baljeet";
```

**What happens behind the scenes:**
```javascript
var name;  // Declaration is hoisted
console.log(name);  // undefined because assignment hasn't happened yet
name = "Baljeet";  // Assignment stays in place
```

**Memory allocation:**
- `var` is hoisted AND initialized as `undefined`
- You can access it before declaration (gets undefined)
- No error thrown

#### let and const Hoisting
```javascript
console.log(x);  // ❌ ReferenceError: Cannot access 'x' before initialization
let x = 10;
```

**What happens:**
```javascript
// TDZ starts here
// console.log(x);  // ❌ Error in this zone!
let x = 10;  // ✨ TDZ ends here
console.log(x);  // ✅ Works, logs 10
```

**Key Difference:**
- `let` and `const` are hoisted but NOT initialized
- They exist in "Temporal Dead Zone" until their declaration
- Accessing them in TDZ throws ReferenceError

### Function Hoisting

#### Function Declarations
```javascript
sayHi();  // ✅ Works! Logs "Hi Navi!"

function sayHi() {
  console.log("Hi Navi!");
}
```

**Why**: Entire function declaration (including body) is hoisted

#### Function Expressions
```javascript
sayBye();  // ❌ Error

var sayBye = function() {
  console.log("Bye!");
};
```

**Why**: Only `var sayBye` is hoisted (as undefined), not the function body

## 3. Temporal Dead Zone (TDZ)

### What is TDZ?
The time between when a variable enters scope and when it's declared.

### Visualizing TDZ

```javascript
{
  // ← TDZ STARTS HERE
  // console.log(user);  // ❌ ReferenceError: user is in TDZ
  
  // Still in TDZ...
  // if (true) console.log(user);  // ❌ Still in TDZ
  
  let user = "Baljeet";  // ← TDZ ENDS HERE
  
  console.log(user);  // ✅ Works: "Baljeet"
  
  if (true) {
    console.log(user);  // ✅ Works: "Baljeet" (outer scope)
  }
}
```

### Why TDZ Exists
- Prevents bugs from hoisting var-like behavior
- Encourages better coding practices
- Catches common mistakes early

### Nested Scope TDZ

```javascript
let x = "Global";

function checkScope() {
  console.log(x);  // ❌ ReferenceError!
  let x = "Local";
}

checkScope();
```

**Why error**: The `let x` inside function creates a NEW TDZ for that block, shadowing the global x.

## 4. Call Stack vs Memory: Recursion

### What is Recursion?
A function calling itself to solve smaller versions of the same problem.

### Call Stack with Recursion

```javascript
function factorial(n) {
  if (n <= 1) return 1;  // Base case
  return n * factorial(n - 1);  // Recursive case
}

factorial(3);
```

**Stack Visualization:**

```
Call: factorial(3)
Stack:
┌────────────────────────┐
│ factorial(3)           │ → 3 * factorial(2)
├────────────────────────┤
│ factorial(2)           │ → 2 * factorial(1)
├────────────────────────┤
│ factorial(1)           │ → returns 1 (base case)
├────────────────────────┤
│ Global                 │
└────────────────────────┘
```

### Stack Overflow: Infinite Recursion

```javascript
function recursive() {
  return recursive();  // No base case!
}

console.log(recursive());  
// ❌ RangeError: Maximum call stack size exceeded
```

**What happens:**
- Each call pushes function onto stack
- Stack grows infinitely
- Stack has maximum size (browser dependent, usually ~15,000 calls)
- Exceeding it causes "Stack Overflow"

# Prefix Sum Applications (Homework Challenges)

## Challenge 1: Range Sum Query

### Problem
Given array and multiple queries (i, j), return sum of elements from index i to j in O(1) time.

### Solution Using Prefix Sum

```javascript
class RangeSum {
  constructor(nums) {
    // Build prefix sum array
    this.prefix = [nums[0]];
    for (let i = 1; i < nums.length; i++) {
      this.prefix[i] = this.prefix[i - 1] + nums[i];
    }
  }
  
  query(i, j) {
    // Sum from i to j = prefix[j] - prefix[i-1]
    if (i === 0) {
      return this.prefix[j];
    }
    return this.prefix[j] - this.prefix[i - 1];
  }
}

// Usage
const rangeSum = new RangeSum([1, 2, 3, 4]);
console.log(rangeSum.query(1, 3));  // 2+3+4 = 9
console.log(rangeSum.query(0, 2));  // 1+2+3 = 6
```

**Time & Space Complexity:**
- **Preprocessing**: O(n) time, O(n) space
- **Each query**: O(1) time

## Challenge 2: Find Pivot Index (Equilibrium Point)

### Problem
Find index where sum of left elements equals sum of right elements.

### Example
`[1, 7, 3, 6, 5, 6]` → Index 3 (left sum = 1+7+3 = 11, right sum = 5+6 = 11)

### Approach 1: Using Prefix Sum (Two Arrays)

```javascript
function findPivotIndex_Approach1(arr) {
  if (arr.length < 1) return "Invalid array";
  
  // Build prefix sum
  let prefSum = [arr[0]];
  for (let i = 1; i < arr.length; i++) {
    prefSum[i] = prefSum[i - 1] + arr[i];
  }
  
  // Check each index
  for (let i = 1; i < arr.length; i++) {
    const leftSum = prefSum[i - 1];
    const rightSum = prefSum[prefSum.length - 1] - prefSum[i];
    
    if (leftSum === rightSum) {
      return i;
    }
  }
  
  return -1;  // No pivot found
}
```

**Complexity**: O(n) time, O(n) space

### Approach 2: Better - Total Sum Method (Optimized)

```javascript
function findPivotIndex_Better(arr) {
  // Calculate total sum
  let totalSum = 0;
  for (let num of arr) {
    totalSum += num;
  }
  
  let leftSum = 0;
  
  // Find pivot
  for (let i = 0; i < arr.length; i++) {
    // Right sum = total - left - current
    const rightSum = totalSum - leftSum - arr[i];
    
    if (leftSum === rightSum) {
      return i;
    }
    
    leftSum += arr[i];  // Update for next iteration
  }
  
  return -1;  // No pivot found
}

// Test
console.log(findPivotIndex_Better([1, 7, 3, 6, 5, 6]));  // 3
```

**Complexity**: O(n) time, O(1) space (better!)

### Dry Run Example

**Input**: `[1, 7, 3, 6, 5, 6]`

```
totalSum = 1+7+3+6+5+6 = 28
leftSum = 0

i = 0: rightSum = 28 - 0 - 1 = 27, leftSum ≠ rightSum → leftSum = 1
i = 1: rightSum = 28 - 1 - 7 = 20, leftSum ≠ rightSum → leftSum = 8
i = 2: rightSum = 28 - 8 - 3 = 17, leftSum ≠ rightSum → leftSum = 11
i = 3: rightSum = 28 - 11 - 6 = 11, leftSum === rightSum ✅ → Return 3

Answer: Index 3 is the pivot
```

## Challenge 3: Running Sum of 1D Array

### Problem
Calculate running sum in-place without extra array.

### In-Place Approach

```javascript
function getRunningSum(arr) {
  // Modify array in-place
  for (let i = 1; i < arr.length; i++) {
    arr[i] = arr[i - 1] + arr[i];  // Use updated previous value
  }
  return arr;
}

// Test
const input = [3, 1, 2, 10, 1];
console.log(getRunningSum(input));  // [3, 4, 6, 16, 17]
```

**Complexity**: O(n) time, O(1) space (optimal!)

### Dry Run

```
Initial: [3, 1, 2, 10, 1]

i = 1: arr[1] = arr[0] + arr[1] = 3 + 1 = 4  → [3, 4, 2, 10, 1]
i = 2: arr[2] = arr[1] + arr[2] = 4 + 2 = 6  → [3, 4, 6, 10, 1]
i = 3: arr[3] = arr[2] + arr[3] = 6 + 10 = 16 → [3, 4, 6, 16, 1]
i = 4: arr[4] = arr[3] + arr[4] = 16 + 1 = 17 → [3, 4, 6, 16, 17]

Result: [3, 4, 6, 16, 17]
```

## Challenge 4: Highest Altitude

### Problem
Find highest altitude reached given altitude gains at each step, starting from 0.

### Example
`gain = [-5, 1, 5, 0, -7]`

```
Starting altitude: 0
After gain[-5]: 0 + (-5) = -5
After gain[1]: -5 + 1 = -4
After gain[5]: -4 + 5 = 1  ← Highest
After gain[0]: 1 + 0 = 1
After gain[-7]: 1 + (-7) = -6

Highest altitude: 1
```

### Optimized Solution (Combined Prefix Sum + Max)

```javascript
function findHighestAltitude(gain) {
  let maxAltitude = 0;      // Start at 0 (initial altitude)
  let currentAltitude = 0;  // Current position
  
  for (let i = 0; i < gain.length; i++) {
    currentAltitude += gain[i];  // Add gain to current altitude
    
    if (currentAltitude > maxAltitude) {
      maxAltitude = currentAltitude;  // Update max if higher
    }
  }
  
  return maxAltitude;
}

// Test
console.log(findHighestAltitude([-5, 1, 5, 0, -7]));  // 1
console.log(findHighestAltitude([-4, -3, -2, -1, 4, 3, 2]));  // 0
```

**Complexity**: O(n) time, O(1) space

### Dry Run

```
gain = [-4, -3, -2, -1, 4, 3, 2]
maxAltitude = 0, currentAltitude = 0

i = 0: currentAltitude = 0 + (-4) = -4, max(-4, 0) = 0 ✓
i = 1: currentAltitude = -4 + (-3) = -7, max(-7, 0) = 0 ✓
i = 2: currentAltitude = -7 + (-2) = -9, max(-9, 0) = 0 ✓
i = 3: currentAltitude = -9 + (-1) = -10, max(-10, 0) = 0 ✓
i = 4: currentAltitude = -10 + 4 = -6, max(-6, 0) = 0 ✓
i = 5: currentAltitude = -6 + 3 = -3, max(-3, 0) = 0 ✓
i = 6: currentAltitude = -3 + 2 = -1, max(-1, 0) = 0 ✓

Result: 0 (never went above starting point)
```

# Optimizations & Comparisons

## moveZeroAtLast: Compare Both Approaches

### Approach 1: Two-Pointer from Ends (Previous File)
```javascript
let s = 0, e = arr.length - 1;
while (s < e) {
  if (arr[s] === 0) {
    [arr[s], arr[e]] = [arr[e], arr[s]];
    s++; e--;
  } else {
    s++;
  }
}
```
- ✅ Less data movement at start (swaps with end)
- ❌ May move elements unnecessarily
- ❌ Not stable (order not preserved)

### Approach 2: Write Pointer (This File)
```javascript
let writePtr = 0;
for (let i = 0; i < arr.length; i++) {
  if (arr[i] !== 0) {
    [arr[writePtr], arr[i]] = [arr[i], arr[writePtr]];
    writePtr++;
  }
}
```
- ✅ Better cache locality (left to right)
- ✅ Stable (maintains order)
- ✅ Easier to understand
- ❌ Slightly more swaps

### Performance Verdict
Write-pointer approach is generally better for modern processors due to cache efficiency.
